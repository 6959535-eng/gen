# Облік генераторів

Мобільний додаток для обліку роботи генераторів і витрат пального. Працює **офлайн**: усі дані
зберігаються в телефоні. Між телефонами дані обʼєднуються через **власний сервер синхронізації**
(коли є інтернет; див. [`apps/server/README.md`](apps/server/README.md)) або зашифрованим файлом `.gen`.
Жодних сторонніх сервісів і аналітики: додаток звертається лише до вашого сервера, тільки по HTTPS.

- Генератори, сесії роботи (живий таймер), заправки, ТО.
- Склад пального окремо від генераторів: надходження, видача (кому / куди), інвентаризація з нестачею / надлишком.
- Фактична витрата між заправками «до повного», підсвічування відхилень від норми, «до ТО».
- Профілі з PIN (адмін / оператор), автоблокування, журнал змін «хто / коли / було → стало».
- Автоматична синхронізація через ваш сервер (Docker + HTTPS, встановлення однією командою).
- Експорт / імпорт зі злиттям, щоденні автокопії, ручні копії, відновлення.
- Інтерфейс українською, темна тема, великі кнопки (зручно в рукавицях).

## 1. Збірка APK

APK збирається в хмарі Expo (EAS Build) — Android Studio на компʼютері не потрібен. Потрібен безкоштовний
акаунт на <https://expo.dev>.

### Один раз

1. Встановіть [Node.js](https://nodejs.org) 22 або новіший.
2. Увімкніть pnpm і встановіть залежності:

   ```bash
   corepack enable
   ```

   ```bash
   git clone https://github.com/6959535-eng/gen.git
   ```

   ```bash
   cd gen && pnpm install
   ```

3. Увійдіть в Expo і створіть проєкт:

   ```bash
   cd apps/mobile && npx eas-cli@latest login
   ```

   ```bash
   npx eas-cli@latest init
   ```

   Команда видасть `projectId` (рядок виду `a1b2c3d4-...`). Вставте його в `apps/mobile/app.config.ts`:

   ```ts
   const EAS_PROJECT_ID = 'a1b2c3d4-...';
   ```

   і закомітьте зміну.

### Кожна збірка

```bash
cd apps/mobile && pnpm build:apk
```

(це те саме, що `npx eas-cli@latest build --platform android --profile preview`).

- Під час **першої** збірки EAS запитає, чи створити ключ підпису (Android keystore) — відповідайте «Так».
- Збірка триває 10–20 хвилин. Наприкінці буде посилання та QR-код для завантаження APK.
- Номер збірки (versionCode) збільшується автоматично, тож новий APK ставиться поверх старого.

> **Важливо: бережіть ключ підпису.** Оновлення встановлюється поверх старої версії (зі збереженням даних)
> лише якщо APK підписано тим самим ключем. Ключ зберігається в EAS; зробіть його копію:
> `npx eas-cli@latest credentials` → Android → `preview` → *Download Keystore*. Тримайте файл і паролі
> в надійному місці.

Профілі збірки (`apps/mobile/eas.json`):

| Профіль       | Для чого                                   | Мережа                       | Пакет              |
|---------------|--------------------------------------------|------------------------------|--------------------|
| `preview`     | робочий APK для команди                     | лише HTTPS до вашого сервера | `ua.gen.oblik`     |
| `production`  | те саме (на майбутнє, окремий канал)        | лише HTTPS до вашого сервера | `ua.gen.oblik`     |
| `development` | dev-клієнт для розробки, ставиться поруч    | є (Metro)                    | `ua.gen.oblik.dev` |

### Альтернатива: локальна збірка (без акаунта Expo)

Потрібні JDK 17+, Android SDK (з прийнятою ліцензією), файл ключа підпису `gen-release.jks`
і файл `signing.env` з паролями (видаються адміну один раз; **у репозиторій не кладіть**).

```bash
cd apps/mobile && ANDROID_HOME=~/android-sdk GEN_SIGNING_ENV=~/gen-signing/signing.env GEN_VERSION_CODE=2 ./scripts/build-apk-local.sh
```

`GEN_VERSION_CODE` — номер збірки: кожного разу на 1 більший за попередній (перший APK мав 1).
Готовий файл — `apps/mobile/dist/oblik-generatoriv-<версія>-<номер>.apk`.

> Локальна збірка й EAS підписують **різними** ключами. Оберіть один спосіб і тримайтеся його,
> інакше оновлення не встановиться поверх старої версії.

iOS збирається з того самого коду (`npx eas-cli@latest build --platform ios --profile preview`), але для
встановлення на iPhone потрібен платний акаунт Apple Developer.

## 2. Встановлення на телефон

1. Отримайте файл `.apk` на телефон: посилання / QR-код зі сторінки збірки на expo.dev, або готовий файл,
   надісланий у Telegram / Signal / поштою, — і відкрийте його.
2. Android попросить дозволити встановлення з цього джерела: **Налаштування → Дозволити з цього джерела**
   (для браузера чи Telegram).
3. Якщо Google Play Protect попереджає про невідомий додаток — **Додаткові відомості → Усе одно встановити**.
   Це звичайне попередження для будь-якого APK не з Google Play.

### Оновлення

Просто встановіть новий APK **поверх** старого — дані збережуться.

> **Не видаляйте додаток перед оновленням!** Видалення стирає всі дані на телефоні (і автоматичні копії).
> Якщо видалити все ж потрібно — спершу зробіть ручну резервну копію і надішліть її собі (розділ 5).

## 3. Перший запуск

На першому телефоні команди: **Створити нову базу** → імʼя адміністратора → PIN (4–6 цифр) двічі.

Далі адмін:

1. **Адмінка → Генератори → + Новий генератор** — назва, тип пального, обʼєм бака, норма витрати (л/год),
   поточні мотогодини, інтервал ТО.
2. **Адмінка → Профілі → + Новий профіль** — оператори (і бажано другий адмін, див. розділ 7).
3. **Дані й копії → Пароль команди** — пароль для файлів експорту та резервних копій (від 8 символів).
   Запишіть його в надійне місце: без нього файл не відкрити.
4. **Склад → Інвентаризація** — фактичні залишки пального на складі; далі **+ Прихід** і **− Видача**.

На **кожному наступному** телефоні не створюйте нову базу, а оберіть **Імпортувати з файла** (розділ 4).

## 4. Перенесення даних на інший телефон

> Якщо у вас є сервер синхронізації — перенесення не потрібне: новий телефон при першому запуску
> обирає **Підключитися до сервера** (див. [`apps/server/README.md`](apps/server/README.md)).
> Нижче — спосіб без сервера, файлом.

### Новий телефон

1. На телефоні, де вже є дані: **Дані й копії → Перенести на інший телефон → Поділитися** → надішліть файл
   `gen-export-….gen` у Telegram / Signal / пошту (або **У папку** → «Завантаження»).
2. На новому телефоні встановіть APK і при першому запуску оберіть **Імпортувати з файла**
   (або в месенджері натисніть на файл → **Відкрити за допомогою → Облік генераторів**).
3. Введіть пароль команди → перегляньте кількість записів → **Імпортувати**.
4. Увійдіть своїм профілем і PIN — профілі переносяться разом із даними.

### Регулярний обмін між телефонами

Кожен телефон може працювати незалежно (наприклад, на різних обʼєктах). Щоб звести дані:

1. Телефон А: **Поділитися** → файл на телефон Б.
2. Телефон Б (адмін): **Дані й копії → Імпортувати файл з іншого телефона** або «Відкрити за допомогою».
3. Перед злиттям видно: скільки **нових**, **оновлених** записів і **конфліктів**. Підтвердьте **Злити дані**.
4. Щоб обидва телефони мали однакові дані — зробіть те саме у зворотному напрямку (Б → А).

Як працює злиття:

- Кожен запис має унікальний ідентифікатор, тож дублів не буде.
- Якщо той самий запис змінювали на обох телефонах — перемагає **пізніша** зміна; обидві версії
  записуються в журнал змін (**Адмінка → Журнал змін**, позначка «Конфлікт імпорту»).
- Видалення теж переносяться.
- Повторний імпорт того самого файла нічого не змінює, а старий файл не перезаписує новіші дані.
- Перед кожним імпортом автоматично зберігається копія поточного стану.
- Після злиття додаток перевіряє дані (дві відкриті сесії на один генератор, сесії, що перетинаються,
  мотогодини, що зменшуються) і показує адміну, що виправити (**Адмінка → Перевірка даних**).

> Годинники телефонів мають показувати правильний час — від нього залежить, яка зміна «пізніша».
> Якщо час телефона явно неправильний, додаток попередить.

## 5. Резервні копії та відновлення

| Копія           | Коли                               | Чим зашифрована   | Де                          | Скільки |
|-----------------|------------------------------------|-------------------|-----------------------------|---------|
| Автоматична     | раз на добу при відкритті додатка  | ключ цього телефона | у памʼяті додатка          | 7 останніх |
| Ручна           | кнопка **Створити резервну копію** | пароль команди    | у памʼяті додатка + куди надішлете | 7 останніх локально |
| Перед імпортом / відновленням | автоматично          | ключ цього телефона | у памʼяті додатка          | разом з автоматичними |

- Автоматичні копії рятують від помилок (випадково видалили, невдалий імпорт), але **не** від втрати
  чи скидання телефона — вони зникають разом із додатком.
- Тому регулярно робіть **ручну** копію і надсилайте її собі або в групу. Якщо ручної копії не було понад
  7 днів, на головному екрані зʼявиться нагадування (термін змінюється в налаштуваннях).

### Відновлення (лише адмін)

**Дані й копії → Відновлення з копії** → оберіть копію зі списку на телефоні або **Обрати файл копії…** →
пароль (для ручних копій) → перевірте дату й кількість записів → **Відновити з цієї копії** → підтвердіть
двічі.

- **Усі** поточні дані на телефоні замінюються даними з копії.
- Перед заміною поточний стан автоматично зберігається (зʼявиться в списку як «Автоматична»), тож
  відновлення можна «відкотити».
- Після відновлення потрібно знову увійти.

Якщо телефон втрачено: встановіть APK на новий телефон → **Імпортувати з файла** → оберіть останню ручну
копію.

## 6. Ролі та безпека

| Що                                   | Адмін | Оператор |
|--------------------------------------|:-----:|:--------:|
| Запуск, зупинка, заправка, ТО, надходження | ✓ | ✓ |
| Редагувати / видаляти свої записи    | ✓ | протягом 24 год |
| Редагувати / видаляти будь-які записи | ✓ | — |
| Генератори, профілі, налаштування    | ✓ | — |
| Журнал змін, перевірка даних         | ✓ | — |
| Резервна копія, експорт              | ✓ | ✓ (якщо пароль команди задано) |
| Імпорт, відновлення, пароль команди  | ✓ | — |

- Вхід: тап на своє імʼя → PIN. Кнопка **«Імʼя · Змінити»** вгорі — швидка зміна користувача.
- Після 5 невірних PIN поспіль профіль блокується на 1 хв; з кожною наступною серією — довше (2, 4, 8… до 60 хв).
- Автоблокування після 5 хв бездіяльності (змінюється в налаштуваннях).
- Зберігається лише хеш PIN із сіллю. PIN захищає від випадкового доступу на спільному телефоні;
  самі файли захищає **пароль команди** (AES-256-GCM, ключ із пароля через scrypt).
- Видалення завжди «мʼяке»: запис зникає зі списків, але лишається в журналі змін.

## 7. Поширені проблеми

**«Додаток не встановлено» при оновленні.** Новий APK підписано іншим ключем (наприклад, проєкт EAS
створювали заново). Відновіть старий ключ через `eas credentials`. Якщо це неможливо — зробіть ручну копію,
видаліть старий додаток, встановіть новий і відновіть копію.

**Оператор забув PIN.** Адмін: **Адмінка → Профілі → (імʼя) → Змінити PIN**.

**Єдиний адмін забув PIN.** Скинути PIN адміна може лише інший адмін — тому заведіть **щонайменше двох
адмінів** (на різних людей).

**Забули пароль команди.** Старі файли без нього не відкрити. Адмін задає новий пароль
(**Дані й копії → Пароль команди**) і одразу робить нову ручну копію; новий пароль треба ввести на всіх
телефонах при першому імпорті.

**Попередження про час телефона.** Час на телефоні раніший за останній запис у базі. Увімкніть
автоматичну дату й час у налаштуваннях Android, інакше нові записи отримають неправильну дату, а злиття
може вибрати не ту версію.

**Додаток пропонує себе для інших файлів у «Відкрити за допомогою».** Так працюють месенджери: вони
надсилають `.gen` як «невідомий файл». Чужий файл додаток не прийме й покаже повідомлення.

## 8. Для розробників

### Структура

```
apps/mobile        Expo (SDK 58) + React Native, TypeScript, expo-router
  src/app/           екрани (маршрути expo-router)
  src/repositories/  єдиний доступ до даних: запис + outbox + журнал змін в одній транзакції
  src/db/            схема Drizzle, підключення expo-sqlite, міграції в drizzle/
  src/services/      експорт / імпорт / копії (backupCore — без привʼязки до платформи)
  src/ui/            компоненти (великі кнопки, цифрова клавіатура…)
  src/dev/seed.ts    демо-дані (лише dev)
packages/shared    zod-схеми, розрахунки, права, злиття, шифрування файла — спільне з майбутнім сервером
apps/server        сервер синхронізації (Fastify + SQLite), інструкція в apps/server/README.md
deploy/            docker-compose, Caddy (HTTPS), install.sh / update.sh для VPS
```

### Команди

```bash
pnpm install
```

```bash
pnpm test
```

```bash
pnpm typecheck
```

Тести репозиторіїв і копій ганяються в Node на справжньому SQLite (better-sqlite3) з тими самими міграціями,
що й на телефоні.

### Запуск на телефоні під час розробки

Додаток використовує нативні модулі, тож Expo Go не підійде — потрібен dev-клієнт:

```bash
cd apps/mobile && pnpm build:dev
```

Встановіть отриманий APK («Генератори (dev)», ставиться поруч із робочим), потім:

```bash
cd apps/mobile && pnpm start
```

На порожній базі на головному екрані є кнопка **Завантажити демо-дані (dev)**: 3 генератори, профілі
«Адмін» (PIN 1111) і «Оператор Петро» (PIN 2222), 2 тижні записів. У робочих збірках її немає.

`pnpm --filter @gen/mobile web` — швидкий перегляд у браузері (SQLite через wasm; системні діалоги,
вибір дати й вібрація там не працюють).

### Зміна схеми БД

1. Змініть `apps/mobile/src/db/schema.ts` (і zod-схему в `packages/shared/src/schemas`).
2. Згенеруйте міграцію:

   ```bash
   pnpm --filter @gen/mobile db:generate
   ```

3. Якщо змінився формат записів у файлі — збільшіть `SCHEMA_VERSION` і додайте перетворення
   в `upgradePayload` (`packages/shared/src/schemas/exportFile.ts`).

Міграції застосовуються при запуску нової версії; перед ними автоматично зберігається копія файла бази
(`db-pre-migration/`, 3 останні).

### Формати й домовленості

- Час — мс UTC; показ — Europe/Kyiv, 24 год, ДД.ММ.РРРР, десяткова кома.
- Обʼєм — цілі мілілітри, мотогодини — цілі хвилини (точне злиття без похибок дробів).
- Кожна таблиця: `id` (UUID v7), `created_at`, `updated_at`, `deleted_at`, `author_id`, `device_id`, `version`.
- Файл `.gen`: `GENF` + версія + заголовок JSON (параметри scrypt, nonce; входить в AAD) +
  AES-256-GCM(gzip(JSON)).

# Сервер синхронізації «Облік генераторів»

Телефони працюють офлайн, як і раніше. Коли є інтернет, вони обмінюються змінами через цей сервер:
відправляють свої (outbox), отримують чужі. Файли `.gen` лишаються запасним способом.

- Node.js + TypeScript, ті самі схеми, права й правила злиття, що в телефоні (`packages/shared`).
- База — SQLite у `/var/lib/gen/gen.db`, щоденні копії в `/var/backups/gen` (30 днів).
- HTTPS — Caddy з безкоштовним сертифікатом Let's Encrypt (оновлюється сам).
- Усе запускається в Docker; назовні відкриті лише порти 22 (SSH), 80 і 443.

---

## Встановлення (один раз)

Потрібен VPS з Ubuntu 24.04 або 26.04 (KVM, від 1 ГБ памʼяті), «без ПЗ», з публічною IPv4.

1. Підключіться до сервера по SSH (дані входу — у панелі хостингу):

   ```bash
   ssh root@IP-АДРЕСА-СЕРВЕРА
   ```

2. Запустіть встановлення:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/6959535-eng/gen/main/deploy/install.sh | bash
   ```

   Скрипт встановить Docker, завантажить код у `/opt/gen`, налаштує брандмауер, запустить сервер,
   отримає HTTPS-сертифікат і ввімкне щоденні копії бази. Перший раз — 3–10 хвилин.

3. Наприкінці буде видно:

   ```
   Адреса для телефона:  1-2-3-4.sslip.io
   Код першого налаштування:  ABCD2345EF
   ```

   Адреса `…sslip.io` збирається з IP сервера — домен купувати не потрібно.
   Власний домен (якщо є): створіть DNS-запис `A` на IP сервера і запустіть встановлення так:
   `curl -fsSL …/install.sh | DOMAIN=gen.example.ua bash`.

Код налаштування також можна знову подивитися (поки не підключено жодного телефона):

```bash
docker compose -f /opt/gen/deploy/docker-compose.yml logs server | grep КОД
```

## Підключення телефонів

1. **Телефон адміна** (з наявними даними): **Дані й копії → Сервер** → адреса + код першого
   налаштування → **Підключити**. Усі дані з телефона відправляться на сервер.
2. **Кожен наступний телефон:** адмін на своєму телефоні — **Сервер → Створити код підключення**
   (одноразовий, 15 хвилин). На новому телефоні при першому запуску — **Підключитися до сервера** →
   адреса + код. Телефон отримає всю базу, далі вхід своїм профілем і PIN.
   Якщо на телефоні вже є дані — підключає адмін через **Дані й копії → Сервер**.
3. Відкликати втрачений телефон: **Сервер → Підключені телефони → Відкликати доступ**.

Синхронізація йде сама: при відкритті додатка, через кілька секунд після кожного запису і щохвилини,
поки додаток відкритий. Стан — на екрані **Сервер** і банером на головній, якщо є проблема.

## Оновлення сервера

```bash
git -C /opt/gen pull && bash /opt/gen/deploy/update.sh
```

Перед оновленням автоматично робиться копія бази.

## Оновлення додатка на телефонах (з версії 1.3.0)

Сервер кожні 5 хвилин підтягує з гілки `ota` репозиторію підписані OTA-оновлення й останній APK
(`/var/lib/gen/ota`, cron `/etc/cron.d/gen-ota`) і роздає їх телефонам:

- `GET /api/updates/manifest` — протокол expo-updates v1 (204, якщо оновлення немає);
- `GET /api/app/latest`, `GET /api/app/apk/<файл>` — новий APK для кнопки «Встановити» в додатку.

Ключа підпису на сервері немає: навіть зламаний сервер не зможе підсунути телефонам чужий код.
Перевірити вручну, що сервер бачить оновлення:

```bash
/opt/gen/deploy/ota-sync.sh && cat /var/lib/gen/ota/updates/*/latest.json /var/lib/gen/ota/apk/latest.json
```

## Резервні копії бази сервера

- Щоночі о 03:15: `/var/backups/gen/gen-РРРР-ММ-ДД.db`, зберігаються 30 днів.
- Скопіювати на свій компʼютер:

  ```bash
  scp root@IP-АДРЕСА-СЕРВЕРА:/var/backups/gen/gen-2026-11-20.db .
  ```

- Відновлення бази з копії:

  ```bash
  cd /opt/gen/deploy && docker compose stop server
  ```

  ```bash
  cp /var/backups/gen/gen-2026-11-20.db /var/lib/gen/gen.db && rm -f /var/lib/gen/gen.db-wal /var/lib/gen/gen.db-shm && chown 1000:1000 /var/lib/gen/gen.db
  ```

  ```bash
  docker compose --env-file .env start server
  ```

  Телефони підтягнуть стан при наступній синхронізації; новіші зміни, які є на телефонах, знову
  відправляться на сервер.

Навіть якщо сервер втрачено повністю, дані лишаються на телефонах: встановіть сервер заново,
і адмін підключить свій телефон кодом налаштування — усе відправиться на новий сервер.

## Як це працює

- **Пристрої.** Кожен телефон отримує власний токен (зберігається в Keystore телефона, на сервері —
  лише хеш). Перший — кодом налаштування з журналу сервера, решта — одноразовими кодами від адміна.
  Після 10 невдалих спроб коду з однієї адреси — пауза 15 хвилин.
- **Push** (`POST /api/v1/sync/push`): телефон відправляє зміни з outbox. Сервер для кожної:
  перевіряє формат (zod), час (не більше ніж на добу вперед від серверного), права користувача
  (`checkPermission` — ті самі правила, але за серверним часом), застосовує last-write-wins
  і записує з новим `seq`. Паралельні правки потрапляють у журнал змін як «конфлікт».
  Відхилену зміну телефон відкочує до серверної версії й показує адміну причину.
- **Pull** (`GET /api/v1/sync/pull?cursor=`): усі записи з `seq` більшим за курсор, порціями по 1000.
- **Повний знімок** (`mode: snapshot`): при підключенні телефона з даними та після імпорту / відновлення
  з файла. Приймається лише від адміна (або від першого телефона, поки сервер порожній).
- PIN-и перевіряються на телефоні; сервер зберігає ті самі хеші й перевіряє роль і активність
  користувача для кожної зміни.
